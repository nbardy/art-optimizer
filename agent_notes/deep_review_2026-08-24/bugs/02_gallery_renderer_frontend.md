# Track BUG-2 — Gallery, Renderer, API, and Frontend Failure Modes

## Severity summary

| Severity | Finding |
|---|---|
| High | gallery generation launches an unbounded grid of worker calls and has no partial-failure cleanup |
| High | renderer/model scope identity can mix materially different runtime configurations |
| High | gallery activation validates only a renderer revision, not its complete representation scope |
| Medium | duplicate activation returns a different response shape |
| Medium | gallery persists host-local absolute paths and trusts them on activation |
| Medium | Diffusers cache lookup has a check-then-render race |
| Medium | gallery modal cannot close while a long render is in progress |
| Medium | taste identity is reconstructed from UI text rather than server data |
| Medium | custom static deployment exposes a misleading bundled experiment catalog API |
| Medium | no artifact retention policy exists |

## 1. High — unbounded gallery fan-out

[`TasteGalleryService.generate`](https://github.com/nbardy/art-optimizer/blob/893e4049105ac56a829edadface3a35a61d087d5/art_optimizer/taste_gallery.py) allows up to:

```text
6 rows × 7 strengths = 42 renders
```

and executes:

```python
artifacts = await asyncio.gather(
    *[asyncio.to_thread(renderer.render, ...) for spec in specs]
)
```

There is no semaphore, queue, progress state, or cancellation.

### Consequences

- procedural rendering may create dozens of CPU-heavy threads and large arrays simultaneously;
- Diffusers rendering serializes inside one renderer lock, but still consumes a pool of waiting threads;
- the HTTP request stays open for the whole grid;
- one failed cell fails the complete request;
- successful artifacts written before failure are orphaned because no manifest is committed and no cleanup runs.

### Fix

Use a persistent `GalleryJob` with bounded concurrency:

```text
created -> rendering(n/m) -> completed | partially_failed | cancelled
```

Each cell has its own state and receipt. The UI streams updates and can close or cancel.

## 2. High — runtime identity is incomplete

The renderer cache request digest is fairly thorough, but session/world/taste identity is not.

`WorldState` and `DesignState` mainly retain:

```text
renderer_revision
control_basis_revision
```

The emergent scope adds prompt and seed. The gallery scope adds model ID, codec revision, and conditioning mode.

Important omissions include some or all of:

- resolved model source;
- resolved checkpoint revision;
- image size;
- dtype;
- CPU offload/device mode;
- steps/guidance and exact embedding strength;
- Diffusers/Torch version;
- direction-bank endpoint prompt digest.

`Settings.from_env` also uses an incomplete runtime fingerprint for the database directory. A server can reopen a session under changed dtype/size/runtime dependencies while retaining the same nominal renderer revision.

### Atlas mixing

[`PersistentPreferenceAtlas.rebuild`](https://github.com/nbardy/art-optimizer/blob/893e4049105ac56a829edadface3a35a61d087d5/art_optimizer/atlas.py) groups evidence by feature revision, control-basis revision, and dimensions. It accepts `renderer_revision` in evidence but omits it from the grouping key. Evidence generated by distinct renderer revisions can therefore be averaged if they share the same basis label.

## 3. High — gallery activation checks too little

Activation checks:

```python
if manifest.renderer_revision != self.service.renderer.revision:
    raise ConflictError(...)
```

It does not compare the full stored representation scope against current capabilities. A gallery generated under a different checkpoint, codec, conditioning behavior, or action interpretation can be activated as though it were current.

The comparison should use one canonical `RepresentationScope` digest shared by sessions, observations, galleries, atlas evidence, and render receipts.

## 4. Medium — activation retry response is not identical

First activation returns an augmented snapshot with:

```python
augmented["gallery_origin"] = event_payload
```

A duplicate request takes the early idempotency branch and returns `emergent.get_snapshot(new_session_id)` without `gallery_origin`.

Thus the same request ID produces different response bodies. Idempotency should return the stored original result exactly.

## 5. Medium — host-local paths in immutable events

`TasteGalleryCell` stores:

```text
image_path
feature_vector
```

inside the event payload. `image_path` is an absolute/local path. This:

- leaks deployment layout;
- is not portable across machines or containers;
- breaks backup/restore assumptions;
- makes events environment-dependent.

Activation trusts the path if it exists and does not recompute/verify `image_digest` before using it.

Persist artifact identity and digest. Resolve paths through an artifact repository at runtime.

## 6. Medium — Diffusers cache race

[`LocalDiffusersRenderer.render`](https://github.com/nbardy/art-optimizer/blob/893e4049105ac56a829edadface3a35a61d087d5/art_optimizer/diffusers_renderer.py) checks the cache before acquiring `_lock`:

```python
cached = load_cached_artifact(...)
if cached is not None:
    return cached

with self._lock:
    # render
```

Two concurrent identical requests can both miss. The second waits for the first, then renders the same artifact again because there is no second cache check inside the lock.

Perform double-checked cache lookup after lock acquisition, or route all rendering through a deduplicating job registry keyed by request digest.

## 7. Medium — gallery traps the user during rendering

[`static/taste_gallery.js`](https://github.com/nbardy/art-optimizer/blob/893e4049105ac56a829edadface3a35a61d087d5/art_optimizer/static/taste_gallery.js) blocks closing while busy:

```javascript
function closeOverlay() {
  if (state.busy) return;
  ...
}
```

For a real 20–42 image grid this can be many minutes. Escape, backdrop click, and close button all fail during that time.

The UI must always close. Cancellation should be explicit and independent from visibility.

## 8. Medium — taste identity is derived from English labels

The gallery integration finds cards and parses:

```javascript
Taste A -> taste-1
```

using `tasteIdFromLabel`. This breaks if:

- label wording changes;
- localization is added;
- labels exceed A–Z;
- server display ordering changes;
- a card is rendered without a resume button.

Render `data-taste-id` from the actual component object, or pass a typed callback directly. The `MutationObserver` integration is a symptom of missing component ownership.

## 9. Medium — custom-static API inconsistency

When `ART_OPTIMIZER_STATIC_DIR` points to a custom UI, `/ui/{experiment}` correctly returns 404. But `/api/ui-experiments` still returns the bundled experiment catalog. A client cannot infer from the catalog that none of those routes are available.

Return the active deployment catalog or include an `available` flag and route capability.

## 10. Medium — no retention or cleanup

Candidate and gallery artifacts accumulate indefinitely. Orphan cases include:

- cancelled/obsolete renderer threads;
- partial gallery failure;
- abandoned galleries;
- old candidate rounds;
- deleted or superseded sessions;
- repeated seed reshuffles.

A retention policy should derive liveness from:

```text
session projections
gallery manifests
favorites/exports
active jobs
explicit archival policy
```

and remove unreferenced artifacts after a grace period.

## 11. Test gaps

Add tests for:

- gallery concurrency cap;
- one cell failing after others succeed;
- retrying incomplete jobs;
- identical concurrent gallery requests;
- same request ID with different specification;
- activation retry exact response equality;
- stale model/checkpoint/codec scope;
- corrupt image digest at stored path;
- user closing/cancelling a busy gallery;
- artifact garbage collection;
- same render request racing through cache.

## Verdict

The gallery's conceptual evidence boundary is good, but its execution path is still a synchronous demo implementation. It should not be used with expensive model grids until render jobs, partial results, cancellation, and full scope validation are implemented.
